# 第一階段：0.1.117 資料快取與診斷隔離

## 改動

- `NNPSnapshotCache` 保存完整歌詞／佇列快照。正常進度 tick 只使用記憶體資料，Spotify 資料通知使快取失效；30 秒恢复讀取處理漏通知。沒有新增常駐 timer。
- Spotify 的資料通知與使用者設定通知分開，主執行緒合併連續通知。資料變更只刷新歌詞／下一首呈現，不再重跑整份設定與 AOD 狀態協調。舊版 Spotify 注入模組使用的設定通知仍可處理。
- 正常編譯排除 Spotify 類別盤點、模型圖描述、歌詞細節診斷欄位、日誌寫入與診斷用 defaults 同步；日志宏在正式版不會求值其參數。
- 正式版只包裝歌詞網路請求。其他 Spotify API 請求的包裝僅在 verbose 診斷版啟用。
- 功能需要的網路 delegate hook 安裝、歌詞表格行判斷、時間歌詞解析、曲目關聯、鎖定輪詢及現有 0.2／1 秒 Spotify timer 均保留。本階段不變更畫面、環境光策略、微移或充電攔截。

## 驗證

GitHub Actions run `37256642427` 的 AOD 與 normal Apple arm64e build 成功。

- 原有充電／位移／亮度、診斷批次、佇列關聯／封面／最後一分鐘測試通過。
- 快取測試：290 次連續讀取只執行一次 loader；通知失效、重複失效、漏通知恢復、資料遺失與時鐘重置均通過。
- 實際偏好設定通知處理程式測試：10 個連續資料通知只讀取一次快照、發送一次資料通知，不重載設定；資料與設定混合通知及舊通知相容性通過。
- Spotify 歌詞模組的 verbose=0 與 verbose=1 均通過 iOS SDK 語法檢查。
- 正常安裝包的 Spotify dylib 不包含模型盤點、類別盤點、runtime log 路徑及診斷啟動鍵的字串。
